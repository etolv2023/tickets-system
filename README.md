# نظام تذاكر الدعم الفني — دليل التسليم

نظام مزيج بين **Jira** و**تذاكر دعم العملاء**: التذكرة = الالتزام تجاه العميل، والصب تاسك = وحدة الشغل الداخلية. عربي بالكامل (RTL)، آمن، وسريع.

> الوثائق التفصيلية: [`FEATURES.md`](FEATURES.md) (24 فيتشر) · [`PLAN.md`](PLAN.md) (المعمارية) · [`CLAUDE.md`](CLAUDE.md) (قواعد الكود).

---

## الستاك

```
PHP 8.2+  ·  Laravel 12  ·  MySQL 8
Blade + Tailwind v3 + Alpine.js  ·  Vite  ·  Quill
```

الباكدجات: `mews/purifier` · `intervention/image` · `maatwebsite/excel`.

> **ملاحظة عن الإصدار:** المشروع على **Laravel 12** مش 11. كل إصدارات Laravel 11 فيها ثغرة CRLF injection مفتوحة (`CVE-2026-48019`) مفيش لها إصلاح في الفرع؛ 12 هي أقرب فرع مرقّع بنفس هيكل 11 وبنفس متطلب PHP 8.2.

## التنصيب

### الطريقة الموصى بها — المعالج

1. فك ضغط المشروع في مجلد على السيرفر، وخلي `public/` هو الـ document root.
2. افتح `http://your-host/` في المتصفح — هيحوّلك تلقائياً لـ `/install`.
3. اتبع الخمس خطوات:
   - **فحص المتطلبات** — PHP والإكستنشنز وصلاحيات الكتابة.
   - **قاعدة البيانات** — لو الداتابيز مش موجودة هتتعمل تلقائياً.
   - **إنشاء الجداول** — migrations + الأدوار والصلاحيات ومصفوفة النقاط.
   - **حساب المدير** — إيميل وباسورد (10 حروف على الأقل).
   - **الإنهاء** — يولّد `APP_KEY`، يقفل وضع التطوير، ويكتب `installed.lock`.
4. بعد التنصيب، `/install` بيرجع **404** تلقائياً.

### مهم للإنتاج

- **شغّل `opcache`** — بدونه الأداء يتدهور بشكل حاد. الإعداد الجاهز في [`deploy/php-production.ini`](deploy/php-production.ini) مع الأرقام اللي تثبت الفرق (كل أهداف الأداء تفشل بدونه وتنجح معه).
- الـ document root **لازم** يكون `public/` — أي حاجة فوقه (`.env`، الكود، المرفقات) مش المفروض توصلها الويب.
- المرفقات بتتخزن في `storage/app/private/` بره `public/` — تأكد إن `storage/` و `bootstrap/cache/` قابلين للكتابة.

## التطوير

```bash
composer install
npm install
cp .env.example .env          # ثم اضبط بيانات الداتابيز
php artisan key:generate
php artisan migrate:fresh --seed
npm run build                 # أو: npm run dev
php artisan serve
```

> على `artisan serve` أثناء تجربة المعالج، استخدم `--no-reload`: السيرفر ده بيعيد تشغيل نفسه لما `.env` يتغيّر، وده بيقطع ريكوست الـ migration. Apache مبيعملش كده.

### معمارية سريعة

- **الكونترولر نحيف** — كل منطق الأعمال في `app/Services/` (15 خدمة).
- **صلاحيات في جداول** (29 صلاحية · 6 أدوار)، بتتقرأ من كاش، وتتغيّر من `/admin/roles` بدون كود.
- **الستايل مقسّم** في `resources/css/` — ممنوع `<style>` أو `style=""` في الـ Blade.
- **التوقيتات UTC في الداتابيز**، العرض بتوقيت القاهرة.

## القرارات المعمارية الحاكمة

1. **`ticket_work_logs` مش `ticket_subtasks`** — الأولاني قرار على مستوى الجهة (فرونت/باك) بيحرّك الحالة والنقاط؛ التاني تخطيط اختياري بيغذّي الكاليندر. القاعدة الرابطة: الجهة اللي عندها صب تاسكس ماتقدرش تقول «خلصت» غير لما كلها تخلص.
2. **النقاط بتتصرف مرة واحدة** عند أول دخول لـ `resolved`. أربع طبقات دفاع ضد الصرف المزدوج، آخرها `UNIQUE(ticket_id, user_id, side)`. تعديل القاعدة مش رجعي. الـ `period` من `resolved_at` مش `now()`.
3. **تسجيل الوقت مالوش علاقة بالنقاط** — عشان محدش يزوّد ساعات علشان النقط.
4. **الأمان:** `Purifier::clean()` على السيرفر لكل HTML من المحرر · `finfo` للملفات المرفوعة · Policy لكل موديل · حماية حقن الصيغ في استيراد **وتصدير** Excel.

### قرار مفتوح (محتاج حسم)

في [`app/Services/PointEngineService.php`](app/Services/PointEngineService.php) تعارض موثّق بين `PLAN § 4.7` (الـ UNIQUE index كخط دفاع أخير) و `F18` (التصحيح صف جديد بنقاط سالبة). الاتنين مايتلمّوش — نُفّذ الـ index (الأقوى)، فمفيش مسار تصحيح لسه. الحل يحتاج قرار: عمود مميِّز في المفتاح، أو التصحيحات خارج الدفتر.
